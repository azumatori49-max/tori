# AI店長（店長サポートAI）— 実装リポジトリ

新規出店1店舗に導入する完全自走型のAI店長システム。
元仕様書の全文はプロジェクトオーナーが管理。本ファイルは実装の拠り所となる要約＋実装済み構成。
**仕様書から意図的に変更した点は `docs/CHANGES_FROM_SPEC.md` を必ず参照すること。**

## 大原則（変更禁止）

1. **判定は機械、表現はAI、決定は人。** 数値判定を Claude にさせない。判定は `gas/engine/rules.js`（純関数・決定論的・テスト可能）。
2. **頭脳はサーバー側（GAS）。** ブラウザのタブをスケジューラにしない。display/ は表示と再生のみ。
3. **基準値と目標値の分離。** 係数（形）は実績から学んでよいが、水準（絶対額）は事業計画から取り、AIに動かさせない。
4. **安全装置は機能より先。** 欠測フォールバック・禁止語フィルタ・キルスイッチ・承認モード・死活監視。
5. **「黙る」より「劣化して動き続ける」。** どの障害でも定型文・キャッシュMP3へフォールバックする。
6. **文体の2階層。** 店長向け＝情報提供と提案（判断は店長に返す）／スタッフ向け＝店長承認済みタスクの具体動作1つのみ。AIが直接スタッフに新規指示を発行しない。
7. **発話の3割は感謝と称賛。** 指示と指摘だけにしない。
8. **音声・モニターに出してはいけない内容**（店長スマホのみ）：人件費・原価の指摘／シフト調整・早上がり提案／特定スタッフに関する内容。

## アーキテクチャ

```
GAS（5分トリガー）
  取得（daily/気象庁/祝日）→ 判定（rules.js）→ 生成（Claude）→ guard →
  TTS(MP3→Drive) → Firebase RTDB 書込 → LINE 配信 → heartbeat
店内モニター: Chrome kiosk が Firebase を購読、表示とMP3再生のみ
スタッフ: LINE でタスク受信 → 完了ボタン → Webhook で記録
```

## ディレクトリ

```
ai-tencho/
├── docs/          RULES.md（人間向け写し）/ OPEN_QUESTIONS.md / SETUP.md / CHANGES_FROM_SPEC.md
├── gas/           clasp 管理の GAS ソース（構成は仕様書 §3 どおり）

```

## Phase ゲート

スクリプトプロパティ `PHASE`（既定 1）で機能を制御する。**Phase 1 は朝礼・日次振り返り・数値表示・日報・feedback記録のみ。** 時間帯指示とアラート発話は Phase 2 から。先の Phase の機能を先回りで実装・有効化しないこと。

## 開発ルール

- GAS は V8。秘密情報はスクリプトプロパティのみ（一覧は docs/SETUP.md）
- 外部APIは指数バックオフで最大3リトライ
- すべての発話は `log` シートに記録（時刻・ルールコード・文面・配信結果）
- `rules.js` `baseline.js` `schedule.js` `guard.js` は純関数を保ち、`test/` のテストを通すこと（`node --test ai-tencho/test/`）
- 日本語コメント。現場の運用担当が読む
- 不明点は推測で埋めず `docs/OPEN_QUESTIONS.md` に追記する
