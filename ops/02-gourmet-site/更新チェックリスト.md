# グルメサイト管理 — 更新チェックリスト

食べログ・ホットペッパーの2サイト更新で起こりがちな「片方だけ更新」「内容ズレ」を防ぐためのチェックリスト。

## 使い方

- 幹部LINEで依頼が来たら、該当するチェックリストをコピーして使う(印刷でも、メモアプリに貼ってもOK)
- コース入力は `ops/tools/course-input-helper.html`(ブラウザで開くだけ)か、Claude Codeの `/gourmet-course` を使うと2サイト分のテキストが一度に作れます

---

## A. 通常変更(営業時間・店舗情報・メニュー変更)

```
【依頼内容メモ】
依頼日:
店舗:
変更内容:

【作業】
□ 幹部LINEの依頼内容を正確に読み取った(店舗名・変更箇所・変更後の値)
□ 食べログ管理画面で修正した
□ ホットペッパー管理画面で修正した
□ 食べログの公開ページで反映を確認した
□ ホットペッパーの公開ページで反映を確認した
□ 2サイトの表示内容が一致していることを見比べた
□ 幹部LINEへ完了報告した
```

### 完了報告の定型文

```
【変更完了報告】
店舗:◯◯
内容:◯◯の変更
食べログ:反映確認済み
ホットペッパー:反映確認済み
```

※即時反映されないサイトの場合は「◯日後に反映予定、反映後に再確認します」と書き、リマインダーを設定する。

---

## B. コース追加・編集(最重要:2サイトのズレ防止)

```
【依頼内容メモ】
依頼日:
店舗:
コース名:
価格(税込):
品数:

【作成】
□ 幹部LINEの原文から、コース名/価格/品数/料理内容/利用条件を抜き出した
□ 食べログ用テキストを作成した(文字数制限内に収めた)
□ ホットペッパー用テキストを作成した(文字数制限内に収めた)
□ 【整合性チェック】2サイト間で以下が一致している
   □ 価格(税込・税抜の表記も含めて)
   □ 品数
   □ 飲み放題の有無・時間
   □ 利用可能な曜日・期間
   □ 利用人数の条件
   □ 予約条件(前日まで/当日OKなど)

【入力】
□ 食べログに入力した
□ ホットペッパーに入力した
□ 食べログの公開ページで表示を確認した(価格・品数・条件を目視)
□ ホットペッパーの公開ページで表示を確認した(価格・品数・条件を目視)

【報告】
□ 幹部LINEへ完了報告した(両サイトの公開URLを添えると確認してもらいやすい)
```

### 短縮のときに削る優先順位(食べログ⇔ホットペッパーで字数が足りないとき)

**削ってよいもの(上から順に削る)**
1. 形容詞・修飾語(「当店自慢の」「贅沢な」など)
2. 料理の細かい説明(「〜を使用した」→ 素材名だけ残す)
3. 重複している情報(説明文とコース内容欄の両方に書いてあるもの)

**絶対に削らない・変えないもの**
- 価格、品数、飲み放題の有無と時間
- 利用条件(曜日・人数・予約期限)
- アレルギー・注意書きに関わる記載

---

## C. 反映待ちがあるときの管理

即時反映されない変更(審査あり・翌日反映など)は忘れやすいので、依頼メモに以下を追記する。

```
□ 反映予定日:◯月◯日
□ 反映確認のリマインダーを設定した(スマホのリマインダー/カレンダー)
□ 反映確認後、幹部LINEへ最終報告した
```
