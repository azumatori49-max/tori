# らくらく臨店チェック（AM改善チェックアプリ）

店舗巡回チェックリストアプリ。写真撮影＋ワンタップ評価で巡回を記録し、アップロードした写真はAI（Gemini）が評価を自動判定。問題点は対応内容・改善期限・担当者まで登録し、宿題を次回来店時に自動表示します。

## 使い方

`index.html` をブラウザで開くだけで動作します（ビルド・サーバー不要）。スマートフォンのブラウザで開くと、写真項目からカメラを直接起動できます。データは端末内（IndexedDB）に保存されます。

```
# ローカルで確認する場合
npx http-server rakuraku-check
```

## 写真のAI自動判定（Firebase AI Logic）のセットアップ

> **AIの判定はあくまで補助です。** AIは評価の候補と理由を提案するだけで、評価は必ず人が「提案を評価に反映」を押して確定します。機能を無効にしたい場合は `index.html` 内の `const FEATURE_AI=true;` を `false` にしてください。

写真から「照明が点灯しているか」「テーブルが清掃されているか」などをAIが判定し、各項目の点数（AI点数）を提案します。AI点数は報告書にも人の評価と並記されます。
標準モデルは無料枠の大きい gemini-3.1-flash-lite（提供終了時は gemini-3.5-flash へ自動フォールバック）。利用にはFirebaseプロジェクトが必要です。**全ユーザー共通で使う場合は、`index.html` の `SHARED_FB_CONFIG` にfirebaseConfigを書き込むと、個人での設定が不要になります**（未設定の場合は下記の手順で各自の管理画面から登録）。

1. [Firebaseコンソール](https://console.firebase.google.com/)でプロジェクトを作成
2. プロジェクトに「ウェブアプリ」を追加し、表示される `firebaseConfig` をコピー
3. コンソールの **構築 > Firebase AI Logic** を開き、セットアップを実行（**Gemini Developer API** バックエンドを選択。無料枠あり）
4. アプリの「管理画面」にある「写真AI自動判定の設定」に `firebaseConfig` を貼り付けて保存し、「接続テスト」で確認。※管理画面のボタンは通常は非表示。URLの末尾に `?admin=1` を付けて開くと、ホーム最下部に表示されます（例：`https://…/rakuraku-check/?admin=1`）

- 自動判定は**カテゴリ移動時にまとめて1回**実行されます（写真1枚ごとには呼ばず、1チェック約5回で完了。呼び出しは4.5秒間隔に自動調整）。各項目の「写真からAI自動判定」ボタンで個別の再判定も可能
- **無料枠の節約には「まとめてAI判定」**：報告・完了タブのボタンで、写真のある全項目をAPI呼び出し1回で判定できます（1項目ずつだと約20回かかるところが1回に）
- AIの判定は**提案**として表示され、「提案を評価に反映」を押すまで評価は変わりません（人の確認を挟む設計）
- 判定理由と信頼度は最終報告書にも記載されます
- 本番運用時は、Google CloudコンソールでAPIキーに「HTTPリファラー制限」を設定することを推奨します

## 共通保存（Cloud Firestore）のセットアップ

完了したチェックを全端末で共有するには、Firebaseコンソールで一度だけ設定します（アプリ側は対応済み）：

1. [Firebaseコンソール](https://console.firebase.google.com/)で対象プロジェクトを開く → **構築 > Firestore Database** → 「データベースを作成」（ロケーションは `asia-northeast1`（東京）推奨 → **本番環境モード**で作成）
2. **構築 > Authentication** → 「始める」 → ログイン方法で **「匿名」を有効化**
3. Firestore Database の「ルール」タブを開き、以下に置き換えて「公開」（認証必須＋tenantIdの一致を強制するA案ルール）：

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /inspections/{id} {
      allow read: if request.auth != null;
      allow create, update: if request.auth != null
        && request.resource.data.tenantId == "default";
      allow delete: if request.auth != null;
    }
    match /photos/{id} {
      allow read: if request.auth != null;
      allow create, update: if request.auth != null
        && request.resource.data.tenantId == "default";
      allow delete: if request.auth != null;
    }
    match /config/{id} {
      allow read, write: if request.auth != null;
    }
  }
}
```

> 注意：匿名認証を使っているため、これは誤操作・他アプリからの混入を防ぐ簡易分離です。会社・店舗ごとの厳密なアクセス分離が必要になったら、Googleログイン＋メンバー管理（B案）に切り替えてください。

設定後、アプリの管理画面の「共通保存（Firestore）」が「接続済み」になれば完了です。各端末に残っていた過去の記録は、接続時に自動でクラウドへ移行されます。

## セキュリティ（無断利用・不正アクセス対策）

3層で保護します。①はアプリに実装済み、②③はFirebase/Google Cloud側の設定が必要です。

1. **アクセスコードゲート（実装済み・現在は無効）** — `index.html` の `ACCESS_CODE_HASH` にコードのSHA-256ハッシュを設定すると、コード入力画面が有効になります（ハッシュは管理画面の「セットアップ支援」で生成可能。`null` で無効）。※静的ページのため確実な防御は②③で行い、①は簡易的な抑止です
2. **Firebase App Check（推奨・AI利用の本命の防御）** — Firebaseコンソール → **App Check** → ウェブアプリに **reCAPTCHA v3** を登録しサイトキーを取得 → `index.html` の `SHARED_APPCHECK_SITE_KEY` に設定 → コンソールで **Firebase AI Logic API の「適用（Enforce）」を有効化**。これで承認したサイト以外からのAI呼び出しはGoogleのサーバー側で拒否されます
3. **APIキーのHTTPリファラー制限** — [Google Cloudコンソールの認証情報](https://console.cloud.google.com/apis/credentials)で対象のAPIキーを開き、「アプリケーションの制限」→「ウェブサイト」で `https://azumatori49-max.github.io/*` を追加。キーが他のサイトで無断利用されるのを防ぎます

なお、チェック記録・写真は各端末のブラウザ内にのみ保存され、サーバーには送信されません（AI判定時の写真はGoogleのAPIに送信されます）。

## 実装済みの仕様

- **基本ルール**
  - 確認項目で写真必須（撮影またはフォルダから選択・複数選択可、項目ごと最大4枚、自動圧縮。接客・笑顔／スタッフの活気／商品品質／挨拶のみ任意、ピーク帯・オペレーション力は写真欄なし）
  - 評価は原則5段階（5点〜1点、各点数に項目別の判定基準文つき）。冷蔵庫温度・フライヤーの油のみ状態選択式。＋AIによる自動判定の提案
  - 点数（評価）と写真が必須（コメント・改善案などは任意）。完了するとランキング・推移に集計される
  - 報告書のPDF変換（印刷）は、写真必須の項目すべてに写真が添付されている場合のみ可能（未添付の項目名を警告表示）
  - 保存した報告書は報告書画面から削除可能。店舗単位の全記録削除は推移画面から
  - PC・スマホとも同じ1カラムのデザインで表示
  - 前回の宿題・タスクを次回来店時にホーム画面に自動表示
- **チェック項目**
  1. 店舗外観・入口 — 照明・看板・提灯・周辺POP（独自5段階基準、写真からAI自動判定対応）／入口（2点以下の場合は理由＋清掃会社依頼の要否→依頼タスク自動作成）
  2. ホール — テーブル／メニュー／椅子（不足数・破損数）／ホール・床
  3. キッチン — 冷蔵庫温度（写真＋評価）／まな板・包丁・ダスター（それぞれ個別に写真＋評価。1点=要買い替え時は購入タスク自動作成）／フライヤー（清掃5段階＋油の状態）／コンロ／ゴミ置き場
  4. 営業・商品品質 — ピーク帯・オペレーション力（0秒スピード、写真なし・点数のみ）／接客・笑顔（0秒スマイル・挨拶、写真任意）／商品品質（写真任意）
  5. 5S — ユニフォーム／挨拶（写真任意）／レジ周り／トイレチェック
  6. 面談 — 面談記録（面談日・開始/終了時間・面談者・被面談者＋5つの質問への自由記述）／次回までの宿題（担当者・期限・優先度・次回来店予定日）
  7. 総合評価・報告 — 店舗名・日時・確認者・全写真・全評価・面談内容・問題項目・宿題・次回来店日・総合点を自動集計。印刷/PDF保存対応
- **面談のAI要約・リスク判定** — 面談の回答をAIが要約し、リスク点数（0〜100）・リスクレベル（高/中/低）・懸念点を提示（補助情報）。リスクが検出された店舗はホーム画面の「⚠ 面談リスクの高い店舗」に自動でリストアップ
- **全店舗ランキング（月別）** — 月ごとのチェックの総合点を低い順に表示し、下位10店舗に「要臨店」バッジ。「◀ 前の月／次の月 ▶」で過去12ヶ月分まで遡って月別のランキングを確認できます（同じ月に複数回チェックした店舗は最新分を採用）。臨店先の優先順位づけに使えます
- **項目別の推移・アラート**
  - 完了したチェックを項目ごとに集計し、全項目の点数推移（直近8回分）を一画面のミニ棒グラフ一覧で表示（最新の点数を強調・改善/悪化の傾向つき）。画面左上に「← 戻る」ボタン
  - 推移画面には直近3回分の面談内容も表示
  - 各項目で3点以下が5回以上になると、推移画面・報告書・チェック中の該当項目・チェック開始時（通知音つき）にアラートを表示
- **ChatGPTでのデータ分析（プロンプト自動生成）**
  - ホームの「ChatGPTでデータ分析」から、全店舗のチェック結果＋面談内容をCSVにまとめ、分析用の指示文（プロンプト）つきでワンタップコピー。ChatGPTに貼り付けると、エリアマネージャーが実行すべき行動（PDCAのDo）だけを店舗ごとに提案させられる。CSVファイルのダウンロードにも対応（Excelで開ける）
  - 推移画面の「ChatGPTで分析」からは、その店舗の点数推移＋面談内容入りの店舗別プロンプトと、全店分析プロンプトの両方をコピー可能
- **自動アップデート通知（UpdateNotifier）**
  - 60秒ごと＋画面を開き直したときに、サーバー上の `index.html` をキャッシュ無しで取得し、中の `APP_VERSION` と今動いている版を比較
  - 新しい版を検知すると画面上部に「新しいバージョンがあります［更新］」バナーを表示。タップでリロードして最新版に切り替わる（×で閉じることも可能）
  - 強制リロードはしないため、写真撮影・入力中に勝手に画面が切り替わることはない（入力途中の下書きは元々端末内に自動保存されている）
  - デプロイ後、開きっぱなしの端末にも数分でバナーが届く。単一ファイル構成のため、`APP_VERSION` の更新がファイル名ハッシュの代わりの更新検知キーになる
- **オフライン保存・自動再送**
  - 完了した記録はUUIDを付けてまず端末内（IndexedDBのoutbox）に保存し、「記録を受け付けました」と即時表示（状態：draft→pending→syncing→synced/failed）
  - 通信可能ならFirestoreへ送信し、サーバー保存の確認後に「送信済み」へ。写真を先に送り、最後に記録本体を確定（途中失敗しても同じIDで再送＝二重登録なし）
  - 自動再送のタイミング：アプリ起動時／onlineイベント／ログイン直後／画面再表示時。「今すぐ再送」ボタンも画面上部に常設
  - 通信のタイムアウトは写真1枚ごとに判定し、送信済みの写真は再送時にスキップ（写真が多い記録も再送のたびに前進して完了する）。クラウド到達を確認できた記録は「未送信」表示を自動で解消
  - 画面上部にオンライン/オフライン・未送信件数・送信状態を常時表示。未送信の記録は一覧に「未送信」バッジ
  - 記録には tenantId・storeId・入力日時（enteredAt）・端末保存日時（savedAt）・サーバー受信日時（receivedAt=serverTimestamp）を付与
- **保存機能**
  - 完了したチェックはクラウド（Cloud Firestore）に保存され、**全端末・全ユーザーで自動共有**。ランキング・推移・危険店舗リストもチーム全体のデータで集計
  - 写真もクラウド保存（報告書を開いたときに読み込み）。クラウド未接続時は端末内保存で動作し、接続後に自動移行
  - 入力途中の下書きは各端末内に自動保存。チェック画面の「保存して中断」→ホームの「続きから再開」
  - **一時保存して提出**：未入力の項目（点数・写真・AI判定）があっても「入力途中のまま一時保存して提出」でクラウドに保存できる。一時保存の報告書は「一時保存」バッジつきで、完了するまでランキング・推移には集計されない。報告書画面の「続きを入力する」でどの端末からでも再開・完了できる
  - 保存済みの報告書・店舗記録の削除はクラウドからも削除
