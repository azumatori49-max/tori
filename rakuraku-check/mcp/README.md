# MCPサーバー（ClaudeやChatGPTから臨店データを参照する）

`worker.js` は、らくらく臨店チェックのデータを **MCP（Model Context Protocol）** で公開する
小さなサーバーです。Cloudflare Workers（無料枠で十分）に置くと、ClaudeやChatGPTの
チャットから「今月の要臨店は？」「柏店の面談内容は？」のように直接データを引けます。

- **読み取り専用**（書き込み・削除は一切できない）
- 写真は含まない（点数・面談テキストのみ）
- 提供ツール：`get_summary`（現況サマリー）／`get_ranking`（月別ランキング）／
  `list_checks`／`get_check_detail`／`get_interviews`／`get_csv`／
  `get_store_metrics`（店舗ごとの売上・FL・KPI。設定方法は「経営指標を有効にする」）

## セットアップ（合計15分くらい・一度だけ）

### ① サーバー用のAPIキーを作る（Google Cloud）

既存のキーはウェブサイト限定（リファラー制限）なので、サーバー用に別のキーを作ります。

1. https://console.cloud.google.com/apis/credentials?project=rakuraku-check を開く
2. 「＋認証情報を作成」→「APIキー」→ 作成されたキーの編集画面を開く
3. 名前：`mcp-server-key` などに変更
4. **アプリケーションの制限：なし** のまま
5. **APIの制限：キーを制限** にして、次の2つだけにチェック：
   - Identity Toolkit API
   - Cloud Firestore API
6. 保存して、キーの文字列（AIza…）を控える

### ② 合言葉（SECRET）を決める

URLの一部になる長いランダム文字列です。例：`IbR9PJj39nbmJmbdCfB6-70cifo8OWKe`
（パスワード生成アプリなどで30文字以上のものを作ってください。**この例をそのまま使わない**）

### ③ Cloudflare Workers にデプロイ

1. https://dash.cloudflare.com/ → 左メニュー「**Workers & Pages**」→「**作成**」→「**Workerの作成**」
2. 名前を `rakuraku-mcp` などにして「デプロイ」→「**コードを編集**」
3. エディタの中身を全部消して、`worker.js` の内容を貼り付ける
4. 先頭付近の2ヶ所を書き換える：
   - `SECRET = "PASTE_LONG_RANDOM_SECRET_HERE"` → ②で決めた文字列
   - `SERVER_API_KEY = "PASTE_SERVER_API_KEY_HERE"` → ①で作ったキー
5. 「デプロイ」を押す。`https://rakuraku-mcp.＜あなたのID＞.workers.dev` というURLができる

接続URLは：`https://rakuraku-mcp.＜あなたのID＞.workers.dev/mcp/＜SECRET＞`

### ④ Claude / ChatGPT につなぐ

**Claude（おすすめ・有料プラン）**
1. claude.ai → 設定 → **コネクタ** → 「カスタムコネクタを追加」
2. 名前：`らくらく臨店チェック`、URL：③の接続URL → 追加
3. チャットで「今月の要臨店は？」と聞くと、Claudeがツールを呼んでデータで答える

**ChatGPT（対応プランのみ）**
設定 → プラグイン（旧コネクター）→ 高度な設定 → 開発者モードON → 作成 → 同じURLを登録

**ChatGPT：カスタムGPT方式（利用者側の登録が不要・おすすめ）**

各利用者にコネクタ登録をさせたくない場合は、管理者が一度だけ「カスタムGPT」を作り、
そのリンクを配る方式が使える（開く人はPlus登録や開発者モード不要）：

1. chatgpt.com（Plus以上）→ 左メニュー「GPT」→ 「作成する」→ 「構成」タブ
2. 名前：`らくらく臨店チェック 分析`、指示（Instructions）：
   「あなたは店舗巡回チェックの分析アシスタント。質問されたらまず getSummary を呼び、
   必要に応じて他のAPIで絞り込む。点数は項目5点満点・総合点100点満点、3点以下は要改善。
   回答は日本語で、店舗名と数字を根拠に示す。」
3. 下の「アクション」→ 「新しいアクションを作成」→ 「URLからインポート」に
   `https://＜Worker名＞.workers.dev/gpt/openapi.json` を入れてインポート
4. 認証：**APIキー** → 認証タイプ **Bearer** → キーに `SECRET`（合言葉）を貼る
5. 右上「作成」→ 公開範囲「**リンクを受け取った人**」で保存 → GPTのリンクをコピー
6. アプリの管理画面 → MCP連携 → 「分析用カスタムGPTのリンク」に貼って保存すると、
   全端末の⚡MCPボタンの「ChatGPTで分析する」がこのGPTを開くようになる

## 経営指標（KPI・売上・FL）を有効にする

店舗ごとの **KPI点数・売上・FL（原価率＋人件費率）** を、アプリで見られるようにする設定です
（AIチャットの `get_store_metrics` でも同じ内容を聞けます）。**やらなくても、ここまでの機能は今まで通り動きます。**

- **売上・FL**：TEAM NOTE（日報を集計しているサイト）が公開している日報データから取ります
- **KPI**：KPIのスプレッドシート（月ごとのタブ）から、直近4か月分の点数を取ります
- どちらか片方だけ設定しても動きます。設定していない側は、その部分が空になるだけです（エラーで止まりません）
- 読み取り専用です。TEAM NOTE にもスプレッドシートにも、何も書き込みません

### 設定する4つの値（`worker.js` の冒頭にあります）

| 名前 | 意味 | 何を入れる？ |
|---|---|---|
| `METRICS_KEY` | アプリが経営指標を読むための**閲覧キー**（合言葉） | 自分で決める長いランダム文字列。**`SECRET` とは別の値にする**（使い回さない） |
| `TEAM_NOTE_ORIGIN` | 売上・FLを取ってくる先（TEAM NOTE のサイト） | サイトのURLの頭の部分。例：`https://xxxx.example.site`（**最後に `/` を付けない**） |
| `KPI_SHEET_ID` | KPIスプレッドシートの目印（ID） | スプレッドシートのURL `https://docs.google.com/spreadsheets/d/`**`ここ`**`/edit` の「ここ」の部分 |
| `KPI_TAB_GIDS` | （任意）月ごとのタブの番号 | 基本は `{}` のままでOK。詳しくは下の「タブが見つからないとき」 |

`PASTE_` の文字が残っている項目は「未設定」と見なされます（エラーで止まることはありません）。

### 手順

1. **閲覧キーを作る**：パスワード生成アプリなどで30文字以上のランダム文字列を作る
   （`SECRET` と同じ作り方。**この画面の例や `SECRET` をそのまま使わない**）
2. **Cloudflare で書き換える**：Workers & Pages → 該当のWorker →「コードを編集」で、冒頭の
   `METRICS_KEY` / `TEAM_NOTE_ORIGIN` / `KPI_SHEET_ID` の3ヶ所を、それぞれの値に書き換えて「デプロイ」。
   （`SECRET` と `SERVER_API_KEY` は設定済みのままでOK。**実際の値はCloudflareの画面上でだけ**入れる）
3. **アプリに登録する**：アプリの管理画面 →「**経営指標**」カードを開き、
   - 取得先URL：`https://＜Worker名＞.＜あなたのID＞.workers.dev`（最後に `/metrics` を付けても付けなくても動きます）
   - 閲覧キー：手順1で作った `METRICS_KEY`

   を貼り付けて保存する（全端末に共有されます）
4. **KPIシートの共有設定を確認する**（次の項目）
5. アプリの店舗画面などに KPI・売上・FL が出れば完了

### KPIシートの共有設定（大事）

Worker はログインせずにスプレッドシートを読むため、シートを **「リンクを知っている全員が閲覧可」** にしておく必要があります。

1. スプレッドシートを開く → 右上「共有」→「一般的なアクセス」を「**リンクを知っている全員**」、権限を「**閲覧者**」にする
2. **注意**：この設定にすると、そのファイルの**全タブ**がリンクを知っている人に見えます。
   給与・個人情報など見せたくないタブが同じファイルに入っていないか確認し、入っていたら別ファイルに分けてください
3. スプレッドシートのURLやIDは社外に出さない（SNS・メール・GitHubに貼らない）

### KPIシートを共有できない／自動で取れないとき（手動取り込み）

シートを「リンクを知っている全員」にしたくない場合や、シートが自動で読めない場合でも、KPIは**アプリの管理画面から手動で取り込めます**。
管理画面 →「経営指標」カードの「**KPIの手動取り込み**」で、月を選び、KPIシートの「店名の列」と「点数の列」をコピーして貼り付けて「取り込む」だけです（全端末に共有されます）。
同じ月に自動取得の値もある場合は、**手動で取り込んだ値が優先**されます。売上・FLはこの影響を受けません。

### 月が変わったら

**何もしなくて大丈夫です。** 今月と前3か月のタブを自動で探します。タブ名が
**「16期9月」のような `＜期＞期＜月＞月`** という決まりのままなら、翌月のタブを作るだけで自動的に切り替わります。

- 期は5月始まりです（2026年5月〜2027年4月＝16期。3・4月は15期）。タブ名の最後に空白が付いていても自動で試します
- 過去の月でタブが見つからないのは普通のことなので、エラーにはなりません（その月が空になるだけ）
- タブ名で探すとき、Googleは「存在しないタブ名」を指定すると**先頭のタブの内容を返す**ことがあります。Worker は「存在しないタブ名で取った内容」と同じものが返ってきた月を「タブ無し」と見なして捨てるので、別の月の点数が紛れ込むことはありません（先頭のタブ自身だけは名前では取れないため、その月は `KPI_TAB_GIDS` で番号を指定してください）
- 売上・FLは TEAM NOTE が公開している月（通常は当月）の分だけです。過去月の売上は出ません

### タブが見つからないとき（`KPI_TAB_GIDS`）

タブ名の付け方が変わった／別のタブの内容が出てしまう、などの場合は、月とタブの番号（gid）を対応づけられます。

1. スプレッドシートで、その月のタブを開く
2. ブラウザのアドレス欄の末尾 `#gid=`**`123456789`** の数字がタブの番号
3. `worker.js` の `KPI_TAB_GIDS` を、たとえば次のように書き換えて再デプロイ：

```
const KPI_TAB_GIDS = { "2026-09": "123456789", "2026-08": "987654321" };
```

（例の数字はダミーです。番号を書いた月はそれを優先し、書いていない月は今まで通りタブ名で探します）

### 動作確認とトラブルシュート

ターミナルが使えるなら（`＜METRICS_KEY＞` は手順1のキー）：

```
curl -s https://…workers.dev/metrics -H 'Authorization: Bearer ＜METRICS_KEY＞'
```

`daily`（売上・FL）と `kpi`（月別のKPI点数）が入ったJSONが返れば成功です。うまくいかない部分は
`errors` に理由が入ります：

| `errors` の内容 | 原因と対処 |
|---|---|
| 〜（TEAM_NOTE_ORIGIN）が未設定です | `TEAM_NOTE_ORIGIN` が `PASTE_` のまま。手順2をやり直す |
| 日報APIを取得できません | URLの間違い、または TEAM NOTE 側が一時的に止まっている。URLを確認して少し待つ |
| 日報APIの形式が想定と異なります | 指定したURLが TEAM NOTE のものではない可能性。URLを確認する |
| 〜（KPI_SHEET_ID）が未設定です | `KPI_SHEET_ID` が `PASTE_` のまま |
| KPIシートを取得できません（共有設定・シートIDを確認） | 共有が「リンクを知っている全員」になっていない／IDの間違い／タブ名が規則と違う |

- 401 が返る → 閲覧キーの間違い（`SECRET` ではなく `METRICS_KEY` を使う）
- 500（サーバー未設定）が返る → `METRICS_KEY` が `PASTE_` のまま
- 結果は5分間だけ保存されます。設定を直した直後は、最長で1〜5分待つと反映されます

### セキュリティの注意（経営指標）

- 閲覧キー（`METRICS_KEY`）は、アプリの管理画面に登録するため**アプリを使う端末に保存されます**。
  売上・FLは社外に出したくない数字なので、キーを社外の人に教えない・スクリーンショットに写さない
- 万一漏れたら：`worker.js` の `METRICS_KEY` を新しい文字列に変えて再デプロイし、管理画面の「経営指標」カードのキーも入れ直す
  （旧キーは即無効。`SECRET` とは独立しているので、AIチャット側の接続はそのまま使えます）
- このリポジトリの `worker.js` には、実際のURL・ID・キーを書き込まない（`PASTE_` のままにする）

## セキュリティの注意

- **接続URLが鍵そのもの**です。社外の人に教えない・SNSに貼らない
- 万一漏れたら：Workerのコードを開いて `SECRET` を新しい文字列に変えて再デプロイ（旧URLは即無効）
- このリポジトリの `worker.js` には鍵を書き込まない（プレースホルダーのままにする）。
  実際の値は**Cloudflareの画面上でだけ**書き換える

## 動作確認

デプロイ後、ターミナルが使えるなら：

```
curl -s https://…workers.dev/mcp/＜SECRET＞ -X POST -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

ツール一覧のJSONが返れば成功。Claudeのコネクタ追加画面でも接続チェックが走ります。

## 項目を追加・変更したとき

アプリのチェック項目を追加・改名したら、`worker.js` 冒頭の `ITEM_NAMES` にも同じ変更を
入れて再デプロイしてください（忘れても壊れはせず、新項目が名前なしになるだけ）。
