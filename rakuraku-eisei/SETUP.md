# らくらく衛生管理 — 導入手順（社外提供用）

元の社内向け衛生管理アプリと同じデザイン・機能のまま、社外に販売できるように
セキュリティと通信安定性を強化した新規アプリです。
**元のアプリ（toriyaro-eisei）とは Firebase プロジェクトもコードも完全に別物**なので、
こちらを何をどう変えても元のアプリには一切影響しません。

## 元アプリとの違い（重要）

| 項目 | 元アプリ | このアプリ |
| --- | --- | --- |
| 店舗の追加・削除 | 画面上は管理者のみだが、DBは誰でも書き込めた | **サーバー側ルールで管理者アカウントのみに制限** |
| 管理者ログイン | パスワードがコードに埋め込み | **Firebase Auth のメール＋パスワード認証** |
| 店舗ログイン | パスワード一覧が誰でも読めた | **パスワードはサーバー側で照合。第三者は読めない** |
| データベース | 全開放（誰でも読み書き可） | **店舗は自店舗の提出のみ・写真もアップロード制限付き** |
| 通信 | 失敗したらエラーのみ | **自動リトライ（最大3回）＋オフラインキャッシュ＋タイムアウト保護** |

## 1. Firebase プロジェクトを新規作成

1. https://console.firebase.google.com で「プロジェクトを追加」（例: `rakuraku-eisei`）
2. **Authentication** → ログイン方法で以下の2つを有効化
   - 「メール / パスワード」（管理者用）
   - 「匿名」（店舗ログイン用）
3. Authentication → ユーザー → 「ユーザーを追加」で **管理者アカウント** を作成
   - メール: `azumatori49@gmail.com`（変える場合は下記「管理者メールの変更」参照）
   - パスワード: 管理者ログインに使うパスワード（強力なものにする）
4. **Firestore Database** を作成（本番モード / ロケーションは `asia-northeast1` 推奨）
5. **Storage** を作成

## 2. アプリに接続情報を設定

プロジェクトの設定 → マイアプリ → 「ウェブアプリを追加」で表示される
`firebaseConfig` の値を、`src/config.ts` に貼り付ける（または `.env` に設定。
`.env.example` をコピーして `.env` を作る）。

## 3. セキュリティルールを反映

```bash
npm install -g firebase-tools
firebase login
firebase use --add   # 作成したプロジェクトを選択
firebase deploy --only firestore:rules,storage
```

（Storage ルールは Firestore を参照するため、初回デプロイ時に権限の自動設定を
求められたら許可してください）

## 4. ビルドと公開

```bash
npm install
npm run build
firebase deploy --only hosting
```

Netlify を使う場合はリポジトリを接続するだけで `netlify.toml` が使われます。

## 5. 使い始める

1. **管理者ページ**（公開URLの末尾に `/admin` を付けたもの。
   例: `https://rakuraku-kanri.web.app/admin`）を開き、管理者パスワードでログイン
   ※管理者入口は店舗ログイン画面のプルダウンには表示されません
2. 「店舗管理」タブで店舗を追加（またはCSV一括登録: `店舗名,パスワード` 形式）
3. 各店舗には「公開URL＋店舗名＋店舗パスワード」を案内する（店舗は公開URLをそのまま開く）
4. **閲覧専用ページ**（見るだけ）は公開URLの末尾に `/view` を付けたもの。
   店舗管理タブの「閲覧専用ページ」カードで閲覧用パスワードを設定し、
   URLとパスワードを見せたい相手（本部スタッフ等）に共有する。
   閲覧ログインでは提出状況・写真の確認のみでき、変更は一切できない

## 管理者メールの変更

管理者メールアドレスは **3か所** を揃えて変更します。

1. `src/config.ts` の `ADMIN_EMAIL`
2. `firestore.rules` の `isAdmin()` 内のメールアドレス
3. `storage.rules` の `isAdmin()` 内のメールアドレス

変更後はルールの再デプロイ（手順3）とアプリの再ビルド（手順4）が必要です。

## セキュリティの仕組み（概要）

- 店舗の追加・削除・パスワード設定は、管理者メールで認証された
  Firebase Auth アカウントのみ許可（クライアントを改造しても不可能）
- 店舗ログインは匿名認証＋「入場券」方式。入場券の作成時にサーバー側ルールが
  パスワードを照合するため、間違ったパスワードではデータに一切触れない
- 店舗パスワードを変更すると、その店舗の古いログインは自動で無効になる
- 写真アップロードは画像のみ・10MB未満・自店舗フォルダのみに制限
