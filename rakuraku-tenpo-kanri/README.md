# らくらく店舗カンリ

<p align="center">
  <img src="public/icon-512.png" width="160" alt="らくらく店舗カンリ ロゴ" />
</p>

**写真を撮って送るだけ。多店舗の衛生チェックを本部が1画面で確認できる業務用Webアプリ。**

紙のチェック表やLINEグループでの写真報告を置き換えます。アプリのインストールは不要。ブラウザで開いて「ホーム画面に追加」するだけで使えるPWA方式です。

---

## こんな課題を解決します

| 現場のよくある課題 | らくらく店舗カンリの答え |
| --- | --- |
| 紙のチェック表が形骸化。本当にやったか分からない | **カメラ直撮り限定**＋写真ごとのアップロード時刻で証拠が残る |
| LINEグループの写真報告が流れて集計できない | 本部ダッシュボードで**全店の実施状況を色分けで1画面表示** |
| 深夜0時をまたぐと「今日の分」がズレる | **朝9時切り替えの業務日**ロジックで深夜報告も自動で前日分扱い |
| 電波が悪くて送れなかった店が「サボり」扱いに | **自動エラーログ**で「送れなかった」と「送らなかった」を区別 |
| 店舗ごとに設備が違いチェック項目が合わない | **店舗別の項目カスタマイズ**（除外・独自項目の追加） |

## 3種類の使い方（ログイン画面で分岐）

1. **店舗スタッフ** — 店舗を選んでパスワードでログイン。毎日のチェックを写真で報告
2. **管理者（本部）** — 管理者パスワードでログイン。全店の状況確認とデータ管理
3. **閲覧モード** — パスワード不要。誰でも「見るだけ」

## 主な機能

### 店舗スタッフ側

- **デイリー（毎日）／ウィークリー（毎週）** の写真チェック。撮影枠に項目名が表示されるので撮り忘れが起きにくい
- **カメラ直撮り限定**（撮り溜め・使い回しの不正防止のため、写真フォルダから選べない仕様）
- 防犯カメラ等の指定項目のみ**複数枚アップロード可**（最大20枚・フォルダ選択可）
- 提出後の**撮り直し・差し替え**が可能
- **提出日を明示表示＋手動変更可**。業務日は朝9時切り替え（深夜1時の報告は自動で前日分扱い）
- **1枚ごとに途中保存**: 7枚中5枚目で失敗しても成功分は保存済み。残りだけ再送でOK
- 通信の瞬断に**自動リトライ（最大3回）**、失敗時は本部へ自動エラー報告
- ログインは一度だけ（端末に保存、一定期間未使用で自動ログアウト）
- 過去の提出履歴を**デイリー14日分・ウィークリー8週分**さかのぼり閲覧

### 管理者（本部）側

- **全店舗ダッシュボード**: 提出済み／一部提出／未提出／LINE報告を色分け集計。日付・週のさかのぼり、未提出のみ絞り込み、店舗名検索
- 写真ごとの**アップロード時刻表示**（実施時間の把握・監査エビデンス）
- **LINE・口頭報告の記録**: アプリ外報告をワンタップで「提出済み（LINE）」扱いに
- **データ修正権限**: 提出の日付/週移動、不要写真の削除、店舗の追加・名称変更・パスワード管理
- **チェック項目の編集**: 全店共通項目の追加・削除、店舗別の除外・独自項目
- **CSVエクスポート**: 提出状況を一覧出力（Excel対応）
- 現場からの**フィードバック受信箱**（返信は店舗側に未読バッジで通知）
- **自動エラーログ**閲覧、古いデータの整理（90日）

## デモモード

Firebase の設定なしで起動すると自動的に**デモモード**になり、サンプル8店舗入りで全機能をその場で試せます（データはブラウザ内にのみ保存）。営業デモ・お客様の試用にそのまま使えます。

- デモ用店舗パスワード: `1111`
- デモ用管理者パスワード: `admin1234`

```bash
pnpm install
pnpm dev   # http://localhost:5173 でデモモード起動
```

## 本番導入（Firebase）

セットアップ手順は [docs/SETUP.md](docs/SETUP.md) を参照してください。概要:

1. Firebase プロジェクトを作成（Realtime Database / Storage / 匿名認証 / Hosting を有効化）
2. `.env.example` を `.env` にコピーして接続情報を記入
3. `pnpm build && firebase deploy`

## 技術構成

- **フロント**: Vite + React 18 + TypeScript + Tailwind CSS
- **バックエンド**: Firebase（Realtime Database / Storage / 匿名認証 / Hosting）
- **PWA**: Service Worker によるキャッシュ管理＋「新バージョンあり」更新通知
- **画像**: 端末内で自動圧縮（長辺1280px）→ 失敗時は元画像フォールバック

## 設計思想

「**衛生管理の証拠を確実に残す**」ことと「**現場が続けられる手軽さ**」の両立。

カメラ直撮り限定で証拠性を担保しつつ、9時切り替え・日付選択・途中保存・エラー自動報告で「現場が損をしない・不正ができない」仕組みになっています。

## ホワイトラベル対応

`src/branding.ts` のアプリ名・履歴日数・業務日切り替え時刻などを書き換えるだけで、販売先ごとのカスタマイズが可能です。ロゴは `src/components/Logo.tsx` と `public/icon.svg` を差し替えてください。
